# WhatsApp-first Operators, staff keep setup

Putrajaya Operators already run on WhatsApp and won't learn a dashboard, so by default an Operator never signs in: staff keep its setup and Schedules, and its Operator contacts get one-way WhatsApp messages (Digest, Booking alerts, Closure done, Payout notice) with signed Operator links for today's list and same-day Closures. Future-date Closures and other changes go through staff by WhatsApp. The operator dashboard stays for Members who want it, with Setup, weekly Schedules and Scan hidden, not removed; Check-in is off and the counter admits Customers by the Digest. Customers stay on email.

## Consequences

- Sending is through SendOnTime on a dedicated Komugo number linked by QR, which can be banned or silently disconnected. Booking alerts are also emailed to owners, failed sends show in the internal dashboard, and messages stay template-shaped so we can move to Meta's WhatsApp Cloud API (paid per message) at about 20–30 Operators.
- Staff are the bottleneck for Operator setup and changes; this holds only at launch scale.
- With Check-in off there is no attendance or no-show data.
